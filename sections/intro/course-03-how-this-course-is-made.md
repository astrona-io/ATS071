# How This Course Is Made

Authors map each section to the official Certified Backstage Associate (CBA) objectives and check the mechanisms against the primary Backstage documentation. They review each example for the component that does the work, the prerequisites and the failure cases that matter.

## How content is checked

Structural checks verify the reading order, the section introductions, the module summaries, the draft marker, the quiz files and the configuration of every lab and playground. The labs and playgrounds are built with static checks only: the lab configuration is validated, the scripts are syntax-checked and the checker is run locally against the descriptor files. A maintainer has not run the labs on a real cluster yet, so treat them as untested until the course says otherwise.

## Maintainers and reporting a mistake

The [contributors](https://github.com/astrona-io/ATS071/graphs/contributors) maintain the material. To [report a mistake](https://github.com/astrona-io/ATS071/issues), name the page and the statement you dispute. The [license](https://github.com/astrona-io/ATS071/blob/main/LICENSE) governs reuse.

## Ownership of names and questions

The exam objectives belong to their respective owners. The teaching text, the labs and the quiz questions are original practice material. The application and team names in the examples are illustrative and have no special technical meaning.
